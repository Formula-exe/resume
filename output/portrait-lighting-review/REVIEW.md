# 静态配色与轻量 Bloom 检查

本轮在现有网站的真实标题、简介和链接上建立独立调色预览，人物沿用上一轮确认的静态采样形状。预览地址：<http://127.0.0.1:8765/output/portrait-lighting-review/>。底部普通按钮支持原配色、Bloom 关闭、Bloom 开启三种状态，也能用 Tab、Enter 和空格操作。

## 画面修改与解决的问题

| 修改 | 解决的画面问题 |
| --- | --- |
| 背景统一为 `#060a12`，导航与左侧遮罩使用同一冷黑色基底 | 原来接近中性的黑底与暖色点、局部背景不够统一；现在空间保持安静，主视觉的透明边缘没有矩形底色。 |
| 远、中、近背景星点分别使用灰蓝、冰蓝、冷白，适当降低亮度 | 近层偏暖、偏亮的背景星点会分走人物注意力；现在背景退后，远近关系通过原来的尺寸和深度保留。 |
| 人物主体改为冷白；只把现有粒子中的 576 个（1.6%）面部亮点设为琥珀色，原来的少量软光点继续使用 | 原图较大面积的暖色容易显得灼热，削弱额头、鼻子、下巴之间的主次。暖色现在集中为细小焦点，不增加粒子。 |
| 脸部亮度系数 1.06、头发 0.92、肩部 0.61，正文提至 `#c8d2e3`、标题提至 `#edf3fc` | 肩部与头发的亮点容易竞争，正文显得灰。脸和头发先被识别，肩部退后；正文有足够对比，阅读区域保持无星点。 |
| 人物层单独使用轻量 Bloom；半分辨率提亮与双向模糊，最大光晕透明度 14% | 原来粒子边缘较硬。开启后只有较亮的点带柔光，保留清楚的轮廓，不把文字或导航一起模糊。 |

## 保持不变的参数

人物仍为 **36,000 个主体粒子 + 33 个原有软光点**，没有新增节点。粒子位置、Z 深度、大小和采样顺序使用冻结的 Float32 数据，调整配色不重新采样。

相机位置 `(0,0,2200)`、FOV `31.815103861051682°`、近远裁切面 `1 / 8000`，方向和投影矩阵均与上一轮一致；不使用轨道控制、自动飞行或指针响应。1254 × 1254 的人物画布按原有右侧容器等比例显示。首屏网格、文字区、视觉区、标题和正文的矩形坐标与现有网站逐项相同。

背景候选星点仍为远层 240、中层 85、近层 22。现有文字避让与视觉区域避让规则保留；在本次桌面视口实际绘制的三层数量、位置和大小都相同。

## 检查结果

- 关闭与开启 Bloom 时，主体人物画布导出的 PNG 完全一致；变化只来自单独的光晕画布。
- 左侧正文及周围留白矩形 `(88,223) — (664,859)` 开关前后逐像素一致。Bloom 的实际变化范围为 `(858,215) — (1413,862)`，始终位于右侧。
- 正文颜色对深色底的计算对比度 **13.0:1**；该数值为配色对比度，不是对抗锯齿边缘的逐像素测量。
- 原配色模式的人物 PNG 与上一轮已交付的静态成形 PNG 逐像素相同。
- 额头、鼻子、下巴轮廓与头发形状清楚；暖色重点少量分布于前侧轮廓，肩部更暗。静止等待、移动指针不会改变形状。
- 键盘开关检查通过；390 像素移动布局无横向溢出，人物粒子数量与相机参数保持一致。
- 浏览器脚本错误、资源加载失败、WebGL 错误均为 0。完整数据见 [verification.json](verification.json)。

## 可调参数与实现

配色、各区域亮度、背景星点亮度和 Bloom 参数集中在 [config.js](config.js)。修改后刷新预览。相机与几何数据放在 [geometry.json](geometry.json) / `geometry.bin`，与配色参数分开，避免调色时误改形状。

Bloom 使用本地 Three.js 的 WebGLRenderTarget 做亮度提取、水平模糊、垂直模糊与透明叠加。阈值 0.46、软阈值区间 0.08、半分辨率 627 × 627、模糊半径系数 1.2、叠加强度 0.70。画布裁切在右侧容器内，HTML 正文不进入后处理。

实现参考：[Three.js WebGLRenderTarget 文档](https://threejs.org/docs/pages/WebGLRenderTarget.html)；亮度阈值限制参与 Bloom 的亮点，参数含义见 [Three.js Bloom 文档](https://threejs.org/docs/pages/UnrealBloomPass.html)。本轮使用小型自定义静态后处理，不加载 UnrealBloomPass 的多级模糊链。
